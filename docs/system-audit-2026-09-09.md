# 系统流程检查与修复

本次检查覆盖终端输入、任务状态、会话结束、失败处理、资源准入、逐轮记录与导出。模型、网关、1000000 上下文及原始轨迹不作修改。

| 问题 | 修复结果 |
| --- | --- |
| 额度请求已处理但响应丢失，重试等待未发送的 Prompt | 使用原请求标识重新核对额度，确认后才首次发送；终端输入结果不确定时仍禁止重发 |
| 第三条对话失败后被自动结束容器 | 未确认或失败的交互保留供恢复；达到次数上限只阻止新增交互，成功、排除或明确结束后再归档 |
| 会话已结束但容器清理前还能追加 Bug | 页面和接口共用会话状态校验，已结束项目、已结束会话及容器不匹配时拒绝追加 |
| 已人工排除的失败仍导致连续失败拦截 | 排除记录保留，但不继续触发自动补题的失败拦截 |
| 后续题导出的环境等级沿用首题 | 按轮次保存环境等级，页面表格和导出读取同一字段；旧记录保留原有回退 |
| 内存不足仍强制启动一个任务，零容量被转换为一 | 资源不足时实际容量为零并停止领取新任务；已有任务继续，状态说明暂停原因 |
| 部分旧接口测试默认连接正式本机服务 | 所有接口测试共用隔离地址校验，仅允许本机 3001 测试服务，写入前拒绝正式服务与远程地址 |
| 实跑快照审核在 Codex 只读环境访问 Docker socket 被拒 | 执行器先实时验证容器身份、镜像、运行状态与工作区挂载，仅传递允许字段组成的脱敏证据；Codex 核对文件清单及依赖，不重复访问 Docker；初始骨架占位不作为业务失败 |

验证：63 项单元测试；完整模拟 32 条对话、22 个会话、7:7:10:1:1 分布、10+10 题额；新增状态接口验证第三轮失败恢复、结束会话拦截、零容量、逐轮环境和排除处理；记录接口验证 30 列、分页、导出次数、重复请求幂等及权限异常拦截；并行模拟验证隔离任务和自动补题。

完整流程与接口使用独立测试数据库及合成记录，不调用真实业务模型，不向正式队列写入测试数据。原始终端轨迹保留，未通过权限检查的数据仍禁止合格导出。
