# 交付追溯、局部返修与批次恢复

2026-09-12 在现有流水线上整合交付总索引、评分字段补丁、上传批次恢复和原题耗时分析。参考 claude-eval-console 的交付关联与局部修订交互；执行器、原终端轨迹、验收、自愈和定时上传继续使用本系统原实现。

## 页面入口

- 项目详情 → 交付追溯：查看原题与最终结果、SessionID、消息 UUID 与原生 PromptID、初始代码、完成代码清单、验收及事实摘要、评分修订、人工确认和导出次数。下载内部 JSON 明细不计 Excel 导出次数。
- 标注数据 → 上传批次：按批次状态筛选和分页，逐条查看暂缓原因、原题和远端回执；重新核验按钮向原上传者排队，不直接发送平台数据。
- 调度区域 → 原题耗时与阶段瓶颈：显示原题全部尝试的墙钟耗时、排队和执行区间，近 30 题明细及按类型/难度/发布版本分组的阶段统计。每题界面最多展示最近 40 个阶段，完整计时仍在本机原始日志和 throughput/latest.json。

交付索引在读取时按当前原始记录生成只读投影，用内容摘要标识版本，追加保存到 delivery_indexes；同一内容不重复保存，旧版不可覆盖。历史材料缺失时明确显示，不能通过索引生成伪造原件。代码清单摘要按验收报告已保存的文件清单计算，不替代逐文件验真。只有已同步、且与原题 SessionID 和消息 UUID 一致的原生 PromptID 才显示为平台标识。

本地索引包含内部资料路径，不能作为平台轨迹附件。平台附件仍由现有原生导出流程生成。标准 Excel 的 30 列、顺序、分页、勾选及导出次数保持原合同。

## 评分修订与恢复

表达、澄清和引用修订使用字段补丁，只允许修改命中的 descriptions、other 或 evidenceRefs；分数、事实与未命中字段由程序保留。事实或分档冲突仍走独立证据复评。正常无问题评分不增加模型调用。

执行器先根据源码、真实轨迹、验收报告和评分规则计算输入摘要，再缓存每个已完成评分子阶段。续跑核对输入和原始输出摘要后复用，失败的后续步骤继续处理；独立调用者没有执行器输入绑定时不启用此缓存。原始完整评分、补丁输出和模型事件均保留，原文件不改写。此过程不运行 Claude 或重新执行项目验收。

## 上传恢复

浏览器上传台账同步批次成员和状态；历史台账缺少已核验的原生标识时显示缺失，新准备的包同步真实标识映射。远端编号存在但尚未核验回执时显示待核对，不能显示为质检通过。

页面恢复请求绑定批次状态、原 attempt 和成员/包摘要。原上传者在 --due 时读取意图，在私有台账锁内重新核对后登记；不抢占运行批次，不改成员和上传记录，不绕过登录或白天窗口。旧版本请求过期后丢弃，不重放到新 attempt。--claim 仍要求真实登录，--batch-plan 仍对原固定成员应用现有回查规则：已有不明确提交只查询回执，已提交成员不再发送，材料变化继续暂缓。

页面按钮只表示已排队核验；结果以原上传任务的实际动作及远端回执为准。批次续传完成之前不宣称上传成功，也不把程序恢复当作平台质检通过。

## 计时、补题与浏览器一致性

阶段计时保留 spanId、起止及排队时间。原题耗时将 504 继续链合并，重叠执行区间仅计算一次；首次交付后返修仍单独记账，缺失时间线不补造。排队和执行之外的间隔包含编排等待，不能全部称为恢复耗时。监控接口在读取完整任务时形成业务题关联投影，不把继续调用当新产出。

补题沿用两条候选缓冲，将最近拒绝草稿及原因传给后续生成；后续规划复用绑定验收报告的能力摘要，仍核对当前源码，只接受实际复现的 Bug。不会为了凑比例生成缺陷，也不以失败草稿释放已经发生的调用额度。

页面各轮询按最新请求/页面生命周期接收结果。标注列表允许在旧轮询等待时翻页，立即作废旧请求并发起最新请求；URL 保存页码，轮询不倒退页码。交付历史版本选择、批次筛选和人工草稿不随轮询切回默认值。浏览器使用的恢复判断与服务端摘要计算拆开，避免 Node 专用模块阻断页面加载。

## 验证与升级

`npm run check:optimization` 检查评分补丁、输入变化后的检查点失效、原题计时、上传窗口、回查与晚到 HTTP 响应。`npm run check:recovery` 保留既有恢复回归。records-api 集成样例在独立端口 3001 验证 30 列、XLSX/CSV、分页、勾选和导出幂等；样例项目完成后先关闭，需继续业务测试时再通过原接口恢复，遵守真实项目数量限制。

`tests/console-optimization-browser.mjs` 仅允许隔离优化工作树和 3001 测试服务，使用真实多页接口响应延迟与实际浏览器操作；不读取生产数据库、不启动模型或向质检平台上传。Playwright 可通过 PLAYWRIGHT_MODULE 指定本机已有安装。

升级先应用新增 delivery_indexes 表迁移，再构建并发布冻结版本。已有作业保留当前已加载版本，新题及可交接的模块采用新版本；保持现有最多三个项目、7:7:10:1:1 比例、10+10 项目题额、两轮 Bug 修复和同会话十次实际调用限制。模型、网关和 1,000,000 上下文不修改。
