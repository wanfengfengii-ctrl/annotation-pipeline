# 出题异常与项目续题

已发送题目被后置审核判定存在事实错误时，该轮一直保留 failed，不能标准导出、生成合格交付包或改为人工标注。此限制只针对该轮数据，不再自动冻结整个项目。

只有原生交互完整结束、权限核验通过、独立运行验收完成、AI 评分及内部数据校验完成，才能进入独立后续规划。恢复时重新核对原题、发送前审批、后置拒绝、原生 SessionID/PromptID、轨迹、验收报告、日志与当前代码；已有审核按发送时记录的题面版本核对，新题仍使用当前规则。

续题前保存 `.retained/manifest.json`、原代码、评分引用文件和异常评测记录。这是内部证据保全及后续项目代码来源，不是合格交付包。后续独立容器可导入经过摘要核验的这些代码；原题和原始轨迹不重写。

原失败回执的完整字节保存在 `<turn>.disputed-evaluation.json`。后续规划仅使用一个权威待投递回执 `<turn>.result.json`，与原执行器的 delivered 摘要及 jobToken 幂等机制共用；不会额外产生第二份会被启动扫描重复投递的 result 文件。加载或解析错误也由规划分支返回，保留 API 中已有的题目、评分和轨迹定位。

有最新复现证据并且仍有额度时，优先在原会话出下一轮 Bug。异常题也计入最多三题、两轮 Bug 修复和十次调用的上限，不能换会话规避。基础可用且无未解决缺陷后才出独立扩展题，独立题新建容器和 Claude 会话，保持原有题型比例、项目额度、禁出和难度审核。

规划成功后 API 在同一次保存中保留旧轮失败并追加下一轮。规划失败保留 nextError，页面提供“仅重试后续出题”；重试不会重新执行旧 Claude、验收或评分，也不能重新规划已有后续题的历史轮次。
