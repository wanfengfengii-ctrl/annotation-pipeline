# 评分阶段的点评对照

SOLO 的 1598、1599 曾因交付完整性描述与同项目旧记录 1419 命中 B-7 分段复读而待返修，已于 2026-09-11 按各自冻结证据返修并通过第二版质检。真实代码和评分依据仍然保留，不能用删除缺陷、同义替换或修改分数消除平台提示。

首次评分和交付校验共用 `scoreInstructions` 的点评要求。`2026-09-11.score-descriptions3` 按用户的三条参考和真实性要求，将展示文字改为每维一小段通俗的操作、结果和影响。先说明具体场景，让没看过源码的人能理解；保留必要的业务数字、工具名或真实报错，不罗列行号、内部报告名、精确测试统计及分档分析。五维各写自己的实际表现，不统一套用先夸后批或升降档结尾。

分数仍按完整五维规则独立判断。所选档与相邻档的事实依据保存在 `processFindings`，可核验的文件路径和行号保存在 `evidenceRefs`，完整测试统计、运行条件和验证范围保存在 `artifactFindings`。独立验收、模型自报和只读源码检查分开归因，未执行或未验证的操作不能写成通过。文字简化不能隐藏缺陷、夸大后果、编造人工体验或改变 AI 来源。

首次评分的表达检查仅对 `descriptions` 中明确的源码行号和分档套话触发既有的一次文字修订；不自动删字、不改分数或结构化证据，不增加上传关卡。业务表格行号、实际输入、必要次数和内部证据中的精确引用不受此展示检查限制。交付校验同时检查真实性和可理解性，不因公开点评没有行号或分档分析而拒收。

评分输入附带本项目较相关的先前业务记录点评，最多四条。只选择当前轮之前已完成、未排除的记录，按实际题目及点评与本轮目标的文字关联排序，再按时间先后打破同分；该排序仅选择对照片段，不模拟平台查重，不判断评分或重复是否合格。原题片段上限 360 字符，每维点评上限 400 字符，截取情况单独标明。不会把整条任务、运行令牌、旧分数、当前记录的旧评分或未来记录加入这份对照。

历史内容是不可信的对照数据，不是本轮事实和指令。评分器仍须独立核对当前冻结源码、原题与原始日志，不能把历史问题混入本轮，也不能宣称这些有限对照等于通过平台查重。此变更不增加上传时的关键词关卡，不重写已保存评分、原题、原生轨迹或远端回执。

点评规则和历史片段都进入评分、交付阶段的缓存摘要，规则变化不能复用旧评分检查点。后续单题通过不可变作业发布采用新版本，已经运行的作业继续使用其已加载版本。规则发布不等于批量重写历史点评；已有记录的返修另存版本，保留原始评分和轨迹。
