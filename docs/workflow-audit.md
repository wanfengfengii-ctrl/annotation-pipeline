# 文档流程与自动化核对

核对日期：2026-09-07。依据：[腾讯文档](https://docs.qq.com/document/DVWVQemZTRm5jZnRJ)。

本系统按用户要求采用 Claude CLI 执行、Codex CLI 准备/快照检查/评分/校验。两个 CLI 均沿用各自配置模型，不注入模型名称。原项目要求人工标注，故本系统输出明确标记为内部 AI 评测，不能直接宣称满足原项目人工交付要求。

| 文档要求 / 作业环节 | 核对结果及处理 |
| --- | --- |
| 禁出题、雷同题 | 已有完整规则组、历史题目比对、独立 Codex 审核与规则版本绑定；语义判断仍依赖模型，不保证零漏判。 |
| 难度下限 | 已有四项难度证据、两项简单特征硬拦截；仅有前轮真实产物和轨迹的后续 Bug 修复可例外。 |
| 空队列补充、任务并行 | 已有仓库白名单/手动历史来源、限额、退避、连续失败熔断、独立工作目录和原子并发控制。M1 Pro 32GB 默认 3 路，上限 4，按负载降低。 |
| 每日题型偏序 | 新增按上海日期统计有效轮次和排队任务，优先补充缺少的题型。3:3:3:2:2:1:1 为实现调度权重，文档没有规定该数值比例；不允许改标签凑比例。 |
| 环境可复现性 | 新增三档环境等级、依赖、启动方式、核验依据。Codex 只读检查不能代替实际容器启动测试，未实测需明确说明。会话续跑检查客户端版本和操作系统一致。 |
| 初始 GitHub 快照 | 已通过 gh 验证完整 40 位 SHA 和可访问提交，整个会话保留初始快照。不自动提交/推送任务仓库。评审者访问权限仍需另行确认。 |
| Prompt、技术栈、版本、轮次标识 | 保存原目标和实际发给 Claude 的完整 Prompt；新增逐轮技术栈、版本、OS、模型记录，避免后轮覆盖历史导出。保留真实 SessionID/PromptID，续跑检查会话一致和消息 ID 不重复。 |
| 逐轮交互 | 新增 Codex 完成/修复/继续/需输入决策；每轮先独立评分、归档，再原子创建下一轮。回写幂等，最多 10 轮，重复目标暂停。可单独关闭自动续跑。 |
| 五维 1–5 分档 | 新增版本化分档规则，包含虚假成功、指令约束、规划、推理与工具效率。 |
| 不满意反馈证据 | 新增 When/What/Impact/正确做法、过程与产物分别说明、模型归因要求；程序核对引用文件和行号存在，Codex 校验内容与分数一致性。存在性检查不等于证据必然证明结论。 |
| 工程异常 | 网络/结果不明不会自动转成模型低分，也不会自动排除有效轮次。重启识别旧子进程；仍存活时阻止同任务重试。已缓存成功执行从后续阶段恢复，无确认结果则标记失败待处理。 |
| 交付材料 | 新增逐轮 tar.gz：实际轨迹、阶段轨迹、评估、校验、Git diff、符合限制的新文件、SHA-256 清单。单个新增文件 10MB、合计 32MB；敏感文件类型/符号链接/超限项列入 omissions，不假装全量。归档留在本机。 |
| 截止时间 | 已有上海 20:00 分界和每轮截止状态。新增按日期导出合格轮次；页面已有过期数量。尚无操作系统通知/无人值守邮件提醒。 |
| 提交 | 本地“校验通过”与外部提交分离；只有填写外部记录后才标记提交。没有擅自填写腾讯文档或发送消息。 |

## 仍需要实际输入或外部系统支持

- 自动补充需要配置真实任务仓库；没有来源时等待，不制造假任务。历史雷同比对仅覆盖本系统已录入任务，未导入此前其他批次题目。
- 本机工作台与云端展示目前是不同数据库；本机 CLI 使用本机队列。云端展示发布不代表远程控制本机，也不上传本机轨迹。
- Claude 上游此前出现超时；模拟 CLI 流水线通过不能证明真实上游持续可用。应在实际可用的 CLI 配置和任务仓库下做首个真实任务验收。
- 图片/附件仍需在 Prompt 明确提供可访问材料；尚无原始附件上传、哈希管理和自动注入功能。
- 原项目人工检查、指定评审账号的仓库权限、外部提交表结构/接入凭据、实际表格写入尚未自动完成。当前自动 AI 评分无法替代原项目要求的人工标注。
- 进程异常恢复依靠本机日志、已缓存阶段与 PID/启动时间；并非系统级守护进程。机器重启后仍需启动本地服务和 runner，待归档任务可能需要人工确认。

## 验证范围

规则/难度/调度单元测试，证据归档与锁恢复单元测试；本地 API 的续跑幂等、暂停、旧进程阻塞和已缓存结果恢复；模拟 CLI 完整流水线覆盖评分失败重试不重跑 Claude、禁出拦截、简单后续修复和自动两轮续跑；并发模拟验证独立目录和资源容量。模拟测试不调用真实模型。

## 2026-09-08：人工二次确认补充

按用户最终选择，继续由 AI 全自动评分和续跑，人工在末尾二次确认。新增 AI 预填、实际核验记录、分维度修改、重点问题复核、返工、历史版本、逐轮人工导出和外部回执锁定。人工操作不阻塞自动流水线，不伪造人工完成。

这是“AI 评分 + 人工复核”工作流，保留两种来源，仍不能宣称满足原项目纯人工标注要求。姓名由操作人填写，系统记录服务端时间与内容，不将自填姓名当作经过身份验证的第三方认证。附件、外部表格自动提交、云端/本机同步等上列剩余项没有因本次新增而自动完成。


### 2026-09-08：截图表头与项目连续作业

- 新增与两张截图完全同名同序的 26 列标注表、Excel 主表，来源记录单独工作表；人工与 AI 的来源仍明确。
- 新增服务端分页、题型/日期/关键词/评分来源/导出次数筛选、按页或筛选结果下载；按轮次累计并对导出请求去重。
- 空队列补充改为 Codex 设计 0-1 项目题，Claude 实现后，在同一项目的后续代码基础上出新题；每道独立题目使用新容器和 SessionID；优先真实 Bug 与 Feature，再理解/重构。
- 每个项目最多 10 题、最多 10 次 Claude 调用，失败重试与排除不释放额度。AI 评分和后续出题不等待人工确认。
- 初始快照继续通过只读 GitHub CLI 获取；源码项目不自动推送，轨迹附件不自动上传，外部提交仍由本人完成后登记。


## 2026-09-08：再次逐项核对与修正

本次重新打开原文，核对第四节作业流程及第七节轮次、截断、评分、难度说明，并检查当前执行器和 API 的实际行为。

| 发现的问题 | 实际修正 |
| --- | --- |
| 原来禁止第二轮出现 0-1，导致从零项目被截断后，继续原题也可能被错判成新项目/修复题。 | 单独记录 continuationOf 与 evaluationPrompt。自动截断续写和手动“继续”保留原分类、难度及完整验收目标，实际 Prompt 仍为“继续”，每次产生新 PromptID、新评分和新归档。真正的修复才归 Bug 修复。 |
| 后续出题处于本轮归档之前，出题出错会使已完成的数据也变成失败。 | 本轮先完成评分、校验、归档，再规划后续；模型决策无效或出题调用失败只记录 nextError，本轮保持可导出。新增“仅重试后续出题”，复用不可变归档结果，不重新调用 Claude、不重评分。 |
| 评分引用只是可变工作目录中的文件路径，后续改代码后难以还原评分依据。 | 归档复制被引用的文件，记录原引用和 SHA-256；人工页面展示评分当时的引用节选。超过归档限制明确报错，不伪造全量。原有累计 git diff 更名，避免当作本轮独有修改。 |
| 相同“继续”文本可能匹配本机会话轨迹中的旧用户消息。 | 优先匹配本轮实际捕获的 PromptID，排除历史轮次 ID；本机轨迹尚未更新时保留本轮流式事件中的真实 ID。 |
| 某轮评分失败后仍能追加下一轮，或后续轮次存在后重跑旧轮，可能覆盖待核验产物。 | 未处理的失败轮次阻止追加；有后续轮次后禁止重跑历史轮次。完成评分/归档后禁止直接改 PromptID/轨迹路径；外部回执只允许首次登记。 |
| 项目内的题型推荐只考虑本项目，未实际使用按天统计的分布。 | 后续出题采用上海当日全局已完成及在途数量，按偏序给出建议；最终类别以真实任务为准，不为比例制造 Bug 或硬改标签。 |
| 交付校验曾通过但归档/执行失败时，表格仍可能显示“AI 校验通过”。 | 表格的通过状态要求整轮形式校验也通过；未完成的轮次显示待校验。 |

用户偏好仍优先于原文：保留 AI 评分后人工二次确认，不声称是纯人工标注；原文允许排除明确工程故障，系统也保留排除，但按用户要求另设更严格的 10 次 Claude 调用上限（失败调用占额度）。10 次是上限，不是要求凑满。旧数据不伪造新增的引用副本。

验证：28 项规则/证据/续写单元测试；API 回归覆盖异常规划不丢本轮、手动继续、历史记录锁定；模拟 CLI 覆盖截断续写、只重试规划时 Claude/评分调用次数不变及归档哈希不变，另保留十轮上限和导出分页/次数测试。模拟 CLI 测试不表示真实模型上游已验收。

未自动完成的外部事项仍见上文：真实源仓库配置、评审者的私有仓库权限、原始附件上传、云端/本机数据同步、外部平台提交。没有凭据或明确目标时不代为写入外部平台。

## 2026-09-08：出题和点评语气

按用户补充要求，新生成题目及每维点评使用一段平淡、口语化文字，允许多句，不添加模板标签、叙述引号、推测或惊讶措辞。表达规则覆盖 Codex 首题生成、任务准备、后续题和评分，程序自动去外围引号，其余问题最多调用 Codex 修订一次，原始和修订轨迹同时保留，分数、难度及结构化证据不得随表达修订改变。

取消评分证据校验时的模板拼接，页面和 Excel 直接展示同一份自然点评，评分依据仍可展开和归档核验；原始需求、代码字面量、已完成记录及 AI 来源不改写。表达检查只能检测明确格式和措辞，事实是否成立仍由证据核验和末尾人工二次确认判断。

## 2026-09-09：Mac 容器要求

当前执行流程已迁移为指定镜像加新空目录，每道独立题目新建容器，启动后导入上一题归档代码；同题继续才保持当前交互进程，停止后不恢复。宿主机上下文检查不再作为容器执行门槛；模型及 100 万配置不修改。GitHub 仅记录参考仓库来源。完整轨迹逐轮复制核验，结束时再次核验后删除容器。详情见 [Mac 容器流程更新](docker-workflow-2026-09-09.md)。

权限追加：预检实际 Claude 进程的免审批参数及 Bash、Read、Write、Edit、Glob、Grep；按完整原生轨迹检测工具权限拒绝，异常拦截评分与合格导出，保留原始证据。保持下午模型、网关及 1000000 上下文不变。
