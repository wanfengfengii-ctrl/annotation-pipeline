# 长项目历史存储

任务历史累积后，完整 JSON 会超过 D1 的单行 2 MiB 限制，导致执行器已完成评分却无法回写，页面持续显示上一阶段。

`lib/task-storage.mjs` 对超过 384 KiB 的任务 JSON 使用无损 gzip/base64 数据库存储，同时保留 SQL 排队、并发、评分来源和自动补题查询需要的小型索引。读取时还原完整任务，核对原始字节长度和查询索引；API、Excel、评分与会话字段不变。压缩只发生在数据库序列化层，不读取、修改或重新打包原生轨迹文件。

旧 JSON 可直接读取，后续正常写入时自动采用新格式，不需要改表或批量回填。任务新增、执行器领取及回写、人工复核事务都使用同一编码器；列表分页和历史导出使用同一解码器。修订号条件更新及并发领取 SQL 继续保持原子性。

部署前备份数据库。已经写入新格式的数据库需要此版本及后续版本读取；不能只回退旧 API 代码。需要回退时应先停写并恢复对应数据库备份，不能裁剪任务历史。超过 32 MiB 的原始任务或压缩后仍过大的任务会明确失败并保留执行器结果文件，不能删除历史或原始轨迹来绕过容量限制。

验证：`node --test tests/task-storage.test.mjs`，并使用隔离数据库验证超过 2 MiB 的任务回写、修订号冲突、记录筛选及导出。
