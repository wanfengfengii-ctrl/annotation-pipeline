# 保留进展的作业恢复

2026-09-12 更新了六处生产恢复策略。

1. Codex 阶段按实质事件的静默时间观察，不设固定总耗时上限。默认静默 15 分钟后暂停，保存会话、完整事件和摘要；同阶段、同逻辑题、同目录、相同输入与输出结构才以明确会话 ID 续接。已完成阶段仍先走完成记录校验。stderr、重复事件不会刷新进展。原 CLI 模型配置保持不变。
2. 独立验收原日志持续落盘并计算完整摘要，模型阅读摘要有大小限制，日志超过 2 MiB 不再终止进程。验收容器也不再按计划总预算自行退出；由该用例执行结束后的清理逻辑释放。日志写入失败仍明确报错，不把丢失证据视为成功。
3. 验收用例在没有新输出达到本步静默阈值时暂停，保存原日志。预算只控制下一步骤准入，已在产生进展的步骤可以继续。取消超时后原命令自动重跑一次；下次先读取未完成步骤日志，定位问题并修订步骤。即使诊断尚未成功，也有单独的失败执行记录供恢复。已完成步骤仅在同题、代码、命令和证据摘要均一致时复用。
4. 项目规划和后处理保留累计次数作为历史，实际重试额度按阶段、失败类别和已发布代码版本分开计算。同一原因仍有限次重试；换了失败原因或发布修复后可以继续，不因旧累计次数永久停止。重复静默仍暂停并交巡检，不无限重试。权限、原生身份、完整归档及禁止上传等校验继续生效。
5. 巡检同时查看运行中阶段的原生进展、Codex 阶段记录和验收进展记录。运行中长期无进展、验收恢复暂停，以及有待处理任务却连续 15 分钟未用满可用执行槽都会进入待处理清单。API 心跳和终端动画不能作为生产进展，不会因此自动重发 Claude 题目。升级排空期间不误报槽位不足。
6. 自动补题先保存生成请求和草稿，网络中断继续处理原草稿。表达审核不合格且没有禁出、重复或难度问题时，最多修订一次 prompt，再独立审核；业务对象、功能范围和其他字段保持原约束。网络失败退避 30 秒至 5 分钟，普通失败短暂等待；认证失败保留草稿并等待认证配置变化。候选通过后仍由服务端检查队列、每日额度和重复项。

进度与恢复记录位于私有 `.runner`。本次改变不改写 Claude 原始 JSONL、已发送题面、既有运行日志或评分，不修改已交付项目源码与原测试。新的执行代码通过冻结发布版本生效；已启动步骤保留自己的执行版本，主执行器用 SIGUSR2 排空后切换。
