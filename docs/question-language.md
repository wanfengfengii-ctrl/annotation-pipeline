# 题目表达

从表达版本 `2026-09-11.plain-language1` 起，所有题型都按通俗、口语化的要求生成和审核，让没有读过项目代码的人能理解要做什么。题面以具体操作、条件和结果说明需求；必要业务术语和代码名称保留并说明作用，避免公文措辞、密集缩写和堆叠条件的长句。此次不改变题型、数量或审核字段协议，基础规则版本继续为 `questions10`，兼容正在运行的主调度器和 API。

0-1 仍保留无编号的项目名称，其他题型直接写正文。正文仍为 180 至 260 字、1 至 2 段，保持原有功能数量、业务细节、禁出、难度、网页和项目边界要求。口语化不意味着减少输入条件、复现步骤、数值或验收要求，也不编造人工经历。

生成、准备、项目后续选题和 Bug 追问共用 `questionInstructions`。独立审核的 `language` 项同时检查可理解性；措辞难懂时指出具体原文及原因，不能只看格式是否合格。仅表达问题沿用既有的一次修订机制，修改 prompt 后重新完整审核，其他结构化要求保持不变。正常业务术语不通过关键词黑名单机械拒绝。

新规则按作业发布版本应用于后续任务。完整规则文件参与政策审核缓存摘要，表达规则变更后未发送的旧草稿也须重新审核，必要时按原范围改写；已经发送的题目保留原文，不追溯否定、不改轨迹或重新发送。活跃作业继续使用其已加载版本。
