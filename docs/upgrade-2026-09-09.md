本次以新腾讯文档和用户提供的实际 Excel 为依据，把表格、页面、生成流程及检查逻辑一起更新。Codex 负责出题、审核、评分和交付检查，Claude CLI 负责完成题目；两个 CLI 都继续使用各自配置的模型，不传模型覆盖参数，不修改用户配置。

## 1. 页面与导出统一为 30 列

| 范围 | 字段 |
| --- | --- |
| A–D | User Prompt、SessionID、TurnID/PromptID、当前对话轮次排序 |
| E–M | 初始环境快照、轨迹文件、环境可复现等级、Harness、Harness 版本、操作系统、任务类型、任务难度、语言/框架 |
| N–W | 交付完整性及描述、指令遵循及描述、任务规划及描述、推理能力及描述、执行能力及描述 |
| X–AD | 其他问题、提交人、提交时间、质检结果、父记录、审核备注、父记录 2 |

字段名和顺序与实际工作簿一致。原 26 列新增 D、AB、AC、AD，主表不插入内部管理字段；AI 来源和导出批次继续放在第二个工作表。

轮次按同一任务中的逻辑顺序固定为 1–10；分页、筛选、排除和重新导出均不重新编号。失败重试保留原轮次，仍占用实际调用额度。历史记录用原数组位置补出轮次，避免数据库分页取出单条记录后丢失原顺序。

样例的两个父记录和审核备注均为空，无法据此判断外部表格关联规则，所以允许手动填写、默认留空，不自动把 SessionID 填入父记录。审核字段修改保留前后值和时间，采用版本校验防止覆盖别人的修改；执行期间和登记交付后禁止修改，保存备注不会代替人工确认。

保留分页、导出次数筛选、本页导出、筛选结果导出及重复请求幂等计数。提交时间写为真正的 Excel 日期值，采用上海时间显示；提交人和时间仍只来自实际回执。旧 26 列批次重新下载继续配套旧表头，新批次使用 30 列，避免历史文件列错位。

## 2. 自定义模型动态读取与 100 万上下文检查

新版规范明确要求开工前核对 1,000,000 tokens。执行器在调度、每轮准备前、实际 Claude 调用前重新读取本机配置，支持全局、项目、本地和常见受管 JSON 配置。模型名称不写死，换模型后下次检查自动更新。提供 `npm run context:check -- /项目路径` 做只读核对。

检查区分三个事实：客户端声明、CLI 本轮报告、网关实际容量。自定义模型可以通过 CLI 支持的 `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 声明窗口；`[1m]` 模型配置也按其 CLI 语义核对。自动压缩阈值不算上下文窗口证据，配置缺失、冲突或禁用 1M 时暂停任务补充；排队任务在调用 Claude 前失败并显示原因，不占用 Claude 调用次数。

系统不替用户添加一个 100 万的数字来宣称模型达标，不探测或公开认证信息。客户端检查通过仍显示网关容量未实测。运行结果若报告其他窗口大小，该轮不能评分或导出为合格记录；已完成调用的证据保留，重试不会重复执行该次 Claude 调用。

切换配置后，新任务使用新配置。已有会话若检测到模型或上下文配置指纹变化，下一次 Claude 调用前暂停，需要结束原会话并新建任务，避免同一会话混合模型。已完成轮次保留原模型、配置检查和轨迹。Codex 编排阶段仍继承 Codex CLI 配置，此次未添加 Codex 被测执行后端，也未覆盖 Codex 的上下文设置。

企业远程托管设置和网关隐藏行为未通过本地 JSON 检查完全覆盖；这类环境仍需按项目方脚本核对。项目方飞书配置脚本没有可直接使用的外部副本，本次没有冒充运行该脚本。

配置语义参考：[Claude Code 模型配置](https://code.claude.com/docs/en/model-config)、[Claude Code 设置](https://code.claude.com/docs/en/settings)。声明上下文之前应先确认相应网关和模型实际支持该窗口。

## 3. Harness、ID 与评分

记录模型名与 Harness 的职责不同：Harness 展示实际执行客户端，模型展示当轮实际报告。现有任务由 Claude Code 执行，导出的 PromptID 来自其原始用户消息。Codex 编排记录单独标注 Codex CLI；遇到原生 `task_started.turn_id` 时提取为 Codex 阶段 TurnID，不把 `thread.started` 的线程 ID 当 TurnID，也不把编排阶段 ID 填入 Claude 的记录。不存在的原生事件保持缺失，不伪造。

规划维度改为看任务拆解、阶段状态追踪、计划更新和歧义处理，不按是否调用特定规划工具加减分。出题与各项点评继续使用平淡、口语化的一段话，允许多个句子；保留任务要求、证据、技术字面量以及未验证的事实边界。

## 4. 保留的流程约束

Codex 先设计 0–1 项目题，Claude 创建项目；后续题目基于真实产物迭代。基础不可用时先修复，不凭空制造 Bug。题型优先顺序、禁止和雷同题审核、难度确定性检查、GitHub CLI 完整 SHA 快照、AI 评分后自动继续及人工最终确认保持生效。

每个项目最多 10 个逻辑轮次，同一会话最多 10 次 Claude 实际调用，失败和排除不能释放额度。新版规范的工程故障排除不放宽用户要求的总调用上限。不同项目按资源并行，同一项目串行；现有机器默认 3 个并行任务，硬上限 4，随 CPU 和内存余量降低新任务准入。

## 5. 交付与验收

先完成字段映射、元数据历史和旧批次兼容，再接上下文动态检查与 Harness 评分规则，最后验证构建、接口和模拟流水线，更新本机执行器及已有私有页面。任务、凭据、原始轨迹和用户提供的 Excel 不随网站源代码上传。

验证覆盖：30 列同名同序、日期类型、公式安全、稳定轮次、审核记录锁定、分页和导出计数；缺少上下文时零调用、换模型不混入原会话、运行窗口冲突不重复调用；连续 10 轮共用项目和会话并分别评分归档。模拟 CLI 验证代表流程可用，不代表真实模型网关已通过 100 万 token 容量测试。
