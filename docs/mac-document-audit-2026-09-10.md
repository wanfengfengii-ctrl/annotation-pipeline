## 尚不能称为完全符合的部分

### 1. 导出和删除没有在原 Mac 终端执行

文档让用户在原终端导出并清理。当前原 Terminal 承载启动及退出；`docker cp` 和 `docker rm` 由 runner 后台执行，使用已绑定的容器 ID 和目录。文件对应关系有程序校验，但不是文档指定的同一终端操作步骤。见 `scripts/docker-runtime.mjs:789`、`:1062`。

建议：让原终端在 Claude 结束后保留受控 shell，由它执行本题导出、校验及删除，并保存退出和导出回执。

### 2. 自动关窗没有等待最终导出成功

文档要求导出前保留原终端。当前清理任务仅检查桥接进程、Docker 客户端退出以及页面显示完成，未检查最终导出已验证或容器已删除。不能保证导出等待或失败时原窗口仍保留。现有日志没有每次关闭的独立时间，因此本次不能断言某个历史窗口确实提前关闭。见 `scripts/terminal-cleanup.mjs:38`、`:127`、`:163`。

建议：把关窗条件绑定到同一题目最终导出成功、容器完成清理，并记录独立关闭时间；导出失败保留窗口。

### 3. 内部 tar 包不等于完整轨迹目录提交包

完整 `/home/node/.claude/projects` 已单独复制到本地且核验；但 `evidence.tar.gz` 只加入本轮轨迹及匹配的主会话文件，没有把 `traceExport` 的完整目录树纳入。当前抽查的 3 个样本每个只有一个原生 JSONL，未发现样本内容遗漏，但不能保证后续有子目录或附加会话文件时提交包仍完整。见 `scripts/evidence.mjs:129`、`:255`。

建议：提供专门的提交包，包含已验证的完整轨迹目录，保留原结构并绑定原始文件清单。

### 4. 缺少提交前统一内容脱敏检查

当前按文件名排除部分敏感配置，但原生/Codex 轨迹、引用整文件和 Git diff 仍原样进入内部归档。Excel 的 XML 转义、公式防护和权限审核不能代替内容脱敏。见 `scripts/evidence.mjs:255`、`:280`、`:337`、`:373`。

本次抽查 3 个成功归档和 1 个异议原件，常见凭据模式候选为 0；3 个归档共 213 个成员的字节、哈希及成员集合一致。抽样未发现凭据不等于所有数据都已完成敏感信息审查。

建议：内部原件保持不可变，另生成经过敏感内容检查的提交副本，保留完整目录、变更清单及检查结果。不要直接修改原始轨迹。

## 文档与用户自定义规则的边界

- 文档没有规定 7:7:10:1:1、每项目两类各 10 题或 Bug 最多两轮，这些来自用户指令。当前有效完成比例为 4:2:6:0:0，目标比例仍在累计调度，不能说本批已经精确达到目标。
- 当前把 Bug 当同一题目的追问，按用户要求复用原会话；如果文档的“每道题”也包括每次 Bug 追问，则该定义与当前规则有差异，需要规范方明确。不能直接把所有 Bug 追问判为违规，也不能说文档明示允许此例外。
- 骨架与上题代码在空环境启动后导入；文档允许主动传入代码。普通 `AGENTS.md` / `CLAUDE.md` 可进一步加入继承排除，但当前入口已禁自动加载，且实际未发现此类文件，属于加固项，不是已发现污染。
- 这份 Mac 文档说明环境与操作流程，没有规定人工评分要求；AI 评分能否作为最终标注交付，需另对照标注说明，不能从本次 Mac 核对推导。

## 用户授权后的修复

### 原终端收尾与关窗

新终端协议 `2026-09-10.mac-terminal2` 在 Claude 与容器 shell 退出后继续保留同一 Mac Terminal。固定命令只允许针对启动时 cidfile 绑定的完整容器 ID 执行 inspect、整个 projects 的 cp、rm 和完成确认。两份完整拷贝一致后才删除容器；finalization 回执和原终端完成状态均核验通过后才结束桥接。关窗前再次验最终目录文件集合和哈希，每次关闭保存独立时间。

复制或删除回执丢失时沿用原 operationId 查询，未确认的删除不重复执行。明确复制失败保留失败目录，用新空目录重试。未实际发题的空会话可完成清理，但不能生成合格提交包。

### 完整证据与最终提交副本

内部归档包含完整原生 projects 树、子会话和空目录。重试创建新归档，旧归档及原始轨迹保持不变。提交包为独立 ZIP/tar，保留每个文件原哈希与副本哈希、文件名映射、脱敏类别与数量；不在清单中回显敏感值。常见凭据、私钥和联系方式按规则处理，未知二进制留待复核，不自动放行。

另补齐了提交时机：评分后标记 awaiting_finalization，允许继续 Bug 追问和项目出题。整道题完成原终端收尾后，由持久队列为该会话各轮生成 submission2 并单独回填 metadata。原轮快照保留在 source-turn/native，最终整目录在 native/projects；原评分、result 回执、archive 和导出计数不重写。上传前重新核验原件、最终回执、完整目录、ZIP 成员与当前敏感规则。

记录可导出状态、Excel/CSV、旧导出批次重新下载、提交登记及人工复核后的回执登记共用最终门槛。旧 submission1 或中间快照不能被当作最终提交材料。无流水线容器的普通导入记录沿用原规则。Excel 仍使用现有字段，下载副本脱敏，数值评分与原始记录保留。
