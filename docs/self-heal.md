# 后台自愈

用户已授权系统自动发现并修复流水线故障。日常状态检查由常驻程序执行，不再定时唤醒模型扫描项目。Mac 登录后由 LaunchAgent 启动，守护进程退出后自动拉起；现有 API 监护及执行器继续保留自己的锁和检查点。

安装：`node scripts/setup-self-heal.mjs --install`。查看：`node scripts/self-heal.mjs --status`。只观察一次：`node scripts/self-heal.mjs --once`。本机开关和预算在 `.runner/self-heal/config.json`，设置 enabled=false 暂停自愈，repairEnabled=false 仅暂停新的模型修复；这些设置不停止生产项目或已启动的修复。

修复工作进程结束、执行器报告失败、归档队列变化及上传故障上报时，立即唤醒守护检查；每 15 秒轮询作为补充。唤醒先核验守护进程身份及协议，不能向旧版或其他进程发送信号。明确报错立即进入处理队列；运行停滞仍要连续核对真实进展，已有修复任务占用时排队，不同时改同一套源码。API/执行器进程确已退出时才重新启动受管服务；活着但慢的 Claude 不会因此被终止或重发。已有网络退避和阶段恢复先继续工作，能安全重试的传输错误只调用一次原有受保护入口。未解决的故障持续跟踪，不因心跳、提交代码或排队就标记完成。已有交付通过也不能掩盖后续规划仍失败。

新故障建立一份私有任务，只读整理相关源码、阶段回执与失败现场，使用当前 Codex CLI 配置执行 `codex exec --sandbox read-only --json --output-schema`；不覆盖模型或强度。大文件允许返回带唯一原文匹配的局部补丁，不必输出整个文件；应用前仍校验完整基线摘要，缺失或多处匹配立即拒绝。结构化补丁经另一轮独立 Codex 复核后，由程序按路径与旧内容摘要应用到隔离 Git worktree。至少补充一个复现原问题的回归测试（可写入已有测试文件），必须原代码失败、修复后通过，再跑恢复/归档/上传的固定回归并构建冻结版本。该工作区没有生产凭据副本；测试不允许访问真实项目、账号或运行中的服务。

默认取消每天六次和同一故障累计两次的本地限制，`maxRepairsPerDay=null`、`maxAttempts=null` 表示不限制次数；这不改变模型账号本身的额度。默认同一时间一个修复任务，每个补丁任务通常包含诊断和独立复核两次模型调用，正常检查不调用模型。常规修复未完成时，立即安排升级诊断，读取此前补丁、复核意见、测试失败和最新现场，定位未能完成的具体原因。升级诊断仍不能解决时立即通知并保留原因；故障、源码和证据均未变化时不重复提交相同诊断。真实条件或修复版本变化后可再次处理，保留历史次数，不靠清零重启。若明确缺凭据、原件或受保护的业务前提，立即通知需要补充的条件，不花模型调用尝试绕过。

不设模型工作的固定总耗时；修复阶段连续二十分钟没有实质事件时保存输出，交升级诊断。失败原因、进程身份与动作意图持久化，守护重启也不重复提交状态不明的恢复操作。诊断只有在提供的 availableRecoveryAction 非空时才可输出 retry，执行时仍须通过现有 API 对原记录身份、阶段及源码的校验。每日 09:00、21:00 的独立复核仅作兜底，故障处理和通知不等待该时间点。

只有主工作区仍干净且基线相同，才快进合并已验证的修复。先构建冻结候选，再升级受管 API、发布后续作业版本，已有作业继续使用原版本，新认领作业加载修复版本。归档模块在当前导出结束后采用已验证的新版本，补题模块在下一次完整生成与审核开始时采用新版本，两者不需要三个项目一起空闲。共享任务锁、资源预算和补题日志保留，候选加载失败仍使用原服务。主协调器收到 SIGUSR2 后继续填补空闲槽位，等自然空闲再更新。旧版协调器已经停止领取而仅剩原终端观察工作时，核验进程归属、已发送摘要、容器和终端身份后，只交接观察进程。原终端及 Claude 不接收停止信号，新观察者没有原发送回执就拒绝恢复，不能重发题目。交接先记账再停止观察者，旧观察者的迟到结果不能覆盖新作业，始终只有一个主执行器。仍有验收、生成或归档工作时等待其自然完成，不设强制结束活跃 Claude 的时限。模块交接与主协调器交接分别记录，不能将版本发布当成生产恢复。新 API 健康检查失败会尝试恢复原 API。原记录、运行日志、原生 JSONL、评分事实、模型网关、上下文、题额及禁传标记都保留。自愈控制器自身、固定质量规则、依赖配置和原生准入不允许由修复模型自动改动，遇到这些变更保留诊断并通知人工处理。

发布完成仍进入观察：原题交付实际通过，或原失败已按既有规则接上同项目独立题并实际发送，才能记录对应恢复结果。两者分别记述，后者不代表旧失败数据通过。无法恢复或需外部处理时写入 notifications.jsonl 并发出一次 Mac 通知，其他项目继续执行。

运行记录在 `.runner/self-heal/state.json`，逐次诊断、补丁、测试日志、发布结果在 `.runner/self-heal/jobs/`，发布交接在 deploy.json。原生轨迹从不复制改写后冒充原件，也不随维护提交进入 Git。修复过程使用现有 Codex CLI 的[非交互执行与结构化输出](https://learn.chatgpt.com/docs/non-interactive-mode)。

SOLO 浏览器上传仍由独立的上传定时任务负责，每天北京时间 08、10、12、14、16、18、20、22 点执行，现场确认登录，按原始 JSONL、查重、先标记再单次提交和真实回执规则完成。新后台进程不控制 SOLO 浏览器，不与上传者竞争。每日凌晨暂停上传，生产和后台自愈照常运行。

上传者发现新的程序故障时，将 `{ "source": "solo-upload", "id": "批次或故障标识", "reason": "实际错误与私有诊断文件路径", "keys": ["taskId:turnId"] }` 保存为私有 JSON，运行 `node scripts/self-heal-event.mjs --report 文件路径`。后台据此启动诊断，不需要再等巡检。事件只接收数据，不执行其中的命令；对应全部记录在本地上传台账存在远端编号且 receiptVerified=true 后，才确认上传故障恢复。身份、原件与权限类拦截保留，不以程序故障名义放行。

## 已知故障、运行页面与恢复演练

冻结源码无法读取时，先验证已保存源码及摘要，将可读取的源码正文同时提供给续题与独立审核；不改变题目审核标准。未发送的独立新题误绑定已归档前题时，核对前题会话、完成证据、权限检查、源码归档和原终端回执，再走同项目重新出题入口。存在已发送或未确认的输入、未知原生消息、缺失原件时不使用该捷径。原终端完成回执丢失但容器已删除且完整轨迹已核验时，归档队列只按原终端协议重试一次；失败次数及条件跨重启保留。其余问题继续诊断，不能无限重发相同动作。

本机页面的生产进展与自动恢复展示项目当前步骤、真实进展时间、最近交付、阻碍、接手者及下一步。守护使用精简状态接口读取恢复必需字段；接口不包含题面、完整模型输出或任务令牌。读取失败保留上次报告并标明过期，不能展示成零个运行项目。每 15 秒上报一次，状态陈旧超过两分钟会提示；上报失败不阻止生产恢复。

新增交付与返修交付分别追加事件，重复回执不重复记账。没有完整时间线的历史记录不反推为今天的新产出。修复消耗按实际阶段启动记录与原始返回的 token 用量统计，缺失用量标为未提供。补丁发布或重试排队不计恢复，需原故障已按现有证据规则确认解决；页面也单列固定流程恢复和模型修复恢复。

运行 `npm run check:recovery` 执行隔离单元与数据库演练，覆盖归档回执丢失、所有者重启、归档失败跨版本恢复、坏候选版本回退、原件不变、重复交付回执、新增与返修区分，以及缺失消耗记录。自愈补丁的固定回归也包含这些检查。完整三个模拟项目并行和自动补题演练使用 `tests/scheduler-flow.test.mjs`，仅接受独立测试数据库的 localhost:3001；假 CLI、临时目录与测试配置隔离真实模型、终端和账号。生产地址在测试入口直接拒绝。

已完成但续题受阻的末轮也可使用原项目恢复入口；排队后不再被旧验收暂停条件挡住，续题仍须验证来源、题额与查重。已停止容器中有本轮原生结束记录时，只导出并恢复完成结果，在独立验收容器继续，不启动旧容器。发送题面匹配仅兼容一个终端前置空格或末尾换行，原始 JSONL 保持原样，其他内容差异仍不接受。
