# 按阶段恢复作业

已完成的题目审核、AI 评分及交付校验使用本题的阶段完成记录恢复。输入、规则、产物、原始轨迹或引用证据变化时，相关记录失效，重新执行该阶段。旧版本没有完成记录时不会猜测通过，需要建立一次新记录。

- 题目未发送时，审核绑定当时的代码和查重历史；发送后保留原题及原审核输入，正常的代码实现不触发重新出题。后置拒绝仍优先阻止交付，不能用旧批准覆盖。
- 验收命令全部完成、仅诊断失败时，绑定镜像、代码、执行计划、日志及环境证据恢复诊断。真实 blocked、依赖失败、源码变化或未执行完整仍重新规划验收。
- 交付进程中断时复用已验真的评分，只重试交付。评分引用内容变化时评分与交付一并失效。归档失败可复用此前成功的交付。
- 完整浏览器安装缓存继续按镜像和版本隔离，复用前验证文件及 smoke 证据；不以缓存代替本题业务验收。
- 调度将执行槽与常驻容器数分开计算，新容器仍受真实 Docker 保留内存/压力预算约束。补题仍有排队、每日额度和冷却限制。负载短抖动有防抖，严重负载及内存不足立即停止新领取。

## 升级与证据

新版 runner 支持 SIGUSR2 排空：停止领取和补充任务，让已开始的 Claude、Codex 阶段完成后退出。只向已在心跳声明 checkpointVersion 的新版 runner 发送该信号，旧版没有此处理器。SIGTERM 仍用于紧急停止并保留原终端。页面更新不需要重启 runner；只有执行逻辑变化时排空再切换。

真实测试与 AI 来源保持不变。每次复用写入 automation.stageReuse，包含原轨迹路径及核验时间。单项目 0-1 和 Feature 各最多十题，单会话最多十次调用、最多两轮 Bug 修复，以及题型比例均未改变。
