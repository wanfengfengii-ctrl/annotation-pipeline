# Mac 容器流程更新

来源：https://docs.qq.com/document/DVVdadUV2dWV4UXZX

此次只调整执行与交付逻辑，模型、网关及 1,000,000 tokens 配置保持现状。

- 每道独立题目对应新容器和全新空 `/workspace`，包括同项目的 0–1、Feature、Bug、理解和重构。启动后导入上一题已归档并核验的代码，记录来源哈希；只有明确的同题继续保留当前交互进程。逻辑轮次及实际 Prompt 均最多 10 次，失败、排除和不确定调用仍占额度。
- 固定指定作业镜像，记录真实镜像摘要；只挂载工作目录，禁止挂载主目录、CLI 配置、Docker socket。保留镜像入口的隔离参数与工具集。
- Codex 在宿主机只读准备、审核、评分与检查。GitHub CLI 只读取得参考仓库来源；该来源不伪装成空容器的初始代码。若任务需要已有源码，应由 Claude 在容器任务开始后按题目获取，不能提前填充目录。
- CLI 自动生成的原始用户消息 UUID 和 SessionID 从完整原生 JSONL 读取，遇到本轮 `turn_duration` 才确认完成，thinking 的 end_turn 不等于作业结束。
- 每轮将完整 projects 目录复制到独立归档目录，运行中的导出前后对比全部文件 SHA-256。评分引用及本轮代码另行冻结，后续修改不覆盖原证据。
- 切换独立题目、完成、10 次上限或人工结束后，向同一终端发送两次 Ctrl-D；停止后两次完整复制进行一致性核验，检查宿主机代码目录存在，再删除指定容器。任何失败都保留容器与错误信息。工作目录不删除。
- 进程中断后允许重新 attach 仍在运行的同一个交互进程；不重启容器、不调用 resume、不重发待确认 Prompt。停止的容器只能归档。已完成执行的缓存允许只重做 Codex 评分。
- Docker 内存预留 2 GiB，每任务 3 GiB、2 核，结合宿主机负载取最小容量。目前 Docker 7.7 GiB，容量 1；暂停的存活容器仍占用名额，已有项目优先。
- AI 评分自动继续，人工末尾复核的来源标记、30 列 Excel、分页与导出次数筛选保持原样。

代码和原始轨迹留在本机，页面提供位置与校验状态。云端与本地队列仍相互独立；云端页面不能直接访问本机 Docker。

## 权限核验

固定镜像的 Claude 使用 bypassPermissions，启动预检核对六种工具、隔离设置和目录写权限，不修改模型、网关或上下文。每轮复制的完整原生轨迹须包含免审批模式且没有工具权限拒绝。记录异常的文件、行号、工具和类别，保留原始内容，阻止自动评分和合格导出；同题后续异常同时阻止该会话此前轮次的合格导出。外部私有服务仍需要有效权限。

代码快照逐文件核验，保留执行位。依赖缓存和敏感配置明确排除；其他无法恢复的排除项会阻止自动导入。

## 本次验证

2026-09-09 实测两个新容器、三个 Prompt：六种工具全部成功调用；第二题导入首题代码并使用新 SessionID；第三个 Prompt 继续第二题并保持其 SessionID。完整原生轨迹均为 bypassPermissions，检测到的权限拒绝为 0；两容器在停止、完整导出校验后移除，模型仍为 auto_model/urm。

53 项单元检查通过；独立测试数据库验证十道题使用十个 SessionID、评分重试不重发 Claude、十次额度、三任务并行与空队列补充，以及 30 列、分页、导出次数和幂等下载。追加验证同题后续权限异常会使此前记录和已保存批次不可再次合格导出。测试记录未写入正式任务数据库。
