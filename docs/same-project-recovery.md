# 同项目续题与提产改进（2026-09-11）

项目题额按用户确认的实际发送口径计算：0-1 与 Feature 各十道业务题。已经发送后失败、被排除以及已预占但发送结果不确定的调用仍计入上限；未发题的被拒草稿不计数，待发送题目预留名额。504 的继续不重复算业务题，但仍消耗原会话实际调用次数。页面分别显示已发送和预留数量。

单题失败不关闭或更换项目。未发送的准备/审核失败、已确认结束的调用错误，以及本轮完成但项目题额未满的情况进入同项目续题规划。正常 504 优先走已有原会话继续；新题只选择有额度、符合源码边界且实质不同的 0-1 或 Feature。两类实际发送题数都满、且没有排队或执行中的后续业务题时才自动结束项目。用户明确关闭仍受尊重，恢复已关闭项目需要显式 resume-project 操作。

规划由原 runner 的任务锁和 Codex 阶段预算管理，不调用 Claude。输入状态不明、工具未返回、原生结束标记缺失或容器身份不符时保留原项目和原容器。确认空闲后，通过原 Mac Terminal 导出并释放该题容器；新题使用新容器和新会话。旧终端无法执行原终端导出时保留原容器，不把它改成后台导出。失败记录、排除和禁传状态、评分、原生 ID、时间及轨迹字节不改写。

Claude 已完成而验收、评分或交付失败时，先按既有检查点自动恢复后处理，最多两次，失败后退避两分钟。两次仍失败就保留当前产物，等待修复验收方法，不自动转去出新题；只有已发送题目本身经审核确认违规，才进入同项目替代题规划。没有已完成的 Claude 检查点时禁止把后处理重试变成重新发题。

末轮代码已完成、原件齐全且未上传时，页面可选择仅重做验收与评分。该操作保留失败历史、重试次数和原题身份，禁止占用新的 Claude 调用。原容器已释放时，还须核对历史环境、原生完成记录、导出回执、原报告及日志摘要，并确认当前源码与原阻塞报告一致；在独立验收容器重新验证，如实记录原容器已归档，不伪装为仍在运行。已有后续题或证据不一致时拒绝此恢复。

验收计划在执行前检查完整相对源码路径、步骤预算及脚本语法。固定检查器只解析 Bash 和可静态提取的内嵌 Python、JavaScript，不执行业务命令；动态拼接脚本不承诺被该检查覆盖。失败只允许一次定向修订，验收项及业务预期不得删减，两个版本和预检日志分别保存。实际页面交互失败时可打印真实控件的标签、角色及可见状态，保留原异常，不自动选第一个控件或绕过断言。重试读取验真的旧命令及失败附近日志，减少重复编写错误验收方法。

已发送题目恢复审核时使用发送前冻结的查重历史，后来新增或被拒的草稿不能反过来作为早期题目的重复来源。后处理在审核或 API 阶段提前失败也保留原生 ID、轨迹导出回执和输出；重试计数保留最初失败阶段，人工点击重试同样计入恢复次数。

新题优先导入该项目最近验真的代码归档；没有可用归档时，只有原会话状态明确且权限核验通过，才冻结当前源码。快照记录来源与摘要，失败过程中未导入的部分改动不能被描述为已完成。新的 Feature 必须基于已有能力，不能把旧 Bug 改名放入新会话规避两轮修复上限。源码或状态不满足继续条件时，保留当前项目等待解决，不另起项目掩盖问题。

续题候选先独立通过禁出、雷同、题面和难度审核，再原子追加一次。调用错误后的原结果保存为 pre-replan-result.json，规划产物另留各次 Codex 原件，回写仍共用唯一 outbox 和 jobToken 幂等机制。重复回写不追加第二道题，规划崩溃不清空原身份或评分。规划失败退避五分钟、十分钟；三次失败后保留项目并交巡检处理选题方向，避免无限消耗额度。

修复规划故障后，对续题规划已阻塞的失败轮次显式重试，会重新进入续题规划，不重发旧题。保留原失败原因、后处理次数与续题尝试次数，新增尝试继续累计；仍需重新核验原会话空闲、冻结源码、题额和新题合规，不重置自动三次上限。Codex 阶段通过内置只读命令读取源码；禁止控制原 Mac Terminal 会话，不限制正常的只读文件查询，也不借助访达或浏览器读取源码。容器状态回传遇到临时网络错误或网关 502/503/504，最多重复提交同一份状态三次；业务错误、模型调用和终端输入不会因该逻辑重试。

全局查重上下文包含每个业务题的目标、题型、操作摘要及拒绝原因，覆盖历史、在途与被拒草稿，取消把每项目历史截为前 4000 字的方式。后续出题在读取源码后确定类别，比例只用于合规目标排序，不能把全新功能硬归为 Feature。暂时缺少目标不代表项目完成。已有未满题额项目达到并行配置时不再补充新项目；入队使用任务集合的版本校验，避免并发补充时越过项目预算。

验收复用固定环境探测和已验证工具准备，增加当前源码索引及相对上次验真清单的变化导航，优先检查入口、变化模块及调用链。每题的业务断言、真实交互和历史未解决问题仍独立运行，文件未变化和旧通过记录不能代替本次验收。评分阶段提前检查引用文件、行号及非空内容，对可定位的附加源码引用同样检查；有问题最多再做一次独立证据复评，不重跑 Claude、不修改产物或原始日志。长段落在本轮不同维度整段重复，或与相关历史描述高度接近时，也触发一次基于原件的复评。该规则是本机表达复核触发器，不声称等于平台相似率；必要事实保留，不改变分数或仅替换同义词规避检查。全局通过量和原有分阶段统计继续保留，续题规划尝试单列，避免算成额外业务题失败。

发布顺序为：测试构建通过，冻结后续作业版本，再切换本地 API。当前已加载的 Claude 作业保持其旧模块，后续领取采用新模块。巡检与 SOLO 上传仍由专用巡检任务负责，不修改模型、网关、100 万上下文、权限核验或上传原件规则。
