# Codex / Claude 自动评测流水线

任务目标 → **Codex CLI 准备任务** → **Codex CLI 检查环境快照** → **Claude CLI 执行** → **Codex CLI 五维评分** → **Codex CLI 校验并生成交付包**。

Codex CLI 沿用现有配置；Claude 使用 Mac 作业文档指定镜像内的配置，模型和 100 万上下文设置保持现状。执行器只传认证，不传模型覆盖参数，也不挂载宿主机配置。Codex 各阶段使用 `codex exec --sandbox read-only --json --output-schema`，其结构化结果、线程 ID 与原始事件分别存档。实际初始快照记录镜像摘要及空工作区；GitHub CLI 在宿主机核验参考仓库，独立保存参考来源。

## 使用

需要 Node.js 22.13+、Python 3、Git、Docker Desktop、已配置的 Codex CLI 和 GitHub CLI。先启动 Docker，并拉取 `adminfather/benzhi-claude-code:20260909-isolated-git`。

```sh
npm install
# 首次初始化才需要执行；已有数据库不要重复执行
npm run db:local
node scripts/init-local.mjs
npm run dev
# 另一个终端
npm run runner
```

打开 http://localhost:3000。填写任务目标、本机 Git 仓库绝对路径，点击“创建并启动流水线”。Codex 自动识别题型、难度、技术栈及验收条件，生成交给 Claude 的 Prompt。后续可追加目标，同项目 0-1 和 Feature 各最多十题，每会话最多初始题加两轮 Bug 修复；失败的 Claude 调用和已排除轮次仍占额度，不能靠重试或排除绕过上限。

常驻运行已构建的页面服务时，使用 `API_WORK_ROOT=/原仓库绝对路径 API_RELEASE_DIR=/包含dist的不可变发布目录 npm run api:local`。服务沿用原仓库 `.wrangler/state` 数据库，关闭开发调试代理、文件监听和热更新，避免无人连接 DevTools 时调试代理持续缓存网络响应。监护每 10 秒检查一次本机接口，连续三次失败后只重启自己启动的 API 进程；首次启动有 60 秒宽限，连续故障按 10 秒至 5 分钟退避。已有外部服务或未知端口占用时不会接管或终止它。状态和锁位于 `.runner/local-api.json` 与 `.runner/local-api.lock`，不影响 Claude 终端与作业容器。

每道独立题目由可见 Mac Terminal 启动交互式 Claude，新建容器，绑定全新且完全为空的 `.runner/<task-id>/questions/<question-id>/workspace` 到 `/workspace`。容器启动后，首题由 Codex 生成并安装最小项目骨架，后续题从上一题已核验的归档导入代码，记录来源清单和 SHA-256；不会导入 CLI 配置。只有 Bug 修复使用当前交互进程，最多两轮修复，合计三条对话，每会话累计调用最多十次。容器不使用 `--rm`，不 start/restart、不使用 continue/resume 参数。

## 自动补充与并发

工作台“调度设置”保存到数据库，下次调度（通常 2.5 秒内）生效。默认启用空队列补充，沿用手动创建任务的仓库；也可指定仓库绝对路径和 Codex 出题范围。无仓库时等待配置，不扫描其他目录。该路径只作为 Codex 出题参考，不会作为 Claude 初始代码挂载。

待执行队列为空且存在空闲执行槽时，Codex 只读检查仓库并设计一个独立项目的 0-1 代码生成题，自动入队。Claude 在骨架中实现首个全新功能后，Codex 继续设计全新功能、Feature、真实 Bug、理解和重构题。比例目标为 7:7:10:1:1，按跨项目累计有效记录和在途任务调度，缺少真实 Bug 时保留比例偏差。出题同样沿用 Codex CLI 模型配置并保存轨迹；模型收到最近 200 个跨仓库任务的标题和 Prompt 摘要以避免语义重复，服务端用规范化 Prompt 指纹做精确去重。语义去重属于模型判断，并非绝对保证。并发补充由数据库原子条件限制，网络失败保留待回写的出题结果，不重新调用模型。

默认每日最多 20 个自动任务（上海时间），每次补充间隔至少 60 秒；出题或回写失败从 5 分钟开始指数退避，最长 1 小时。最近 3 个自动任务均执行失败时暂停补充，处理并重试失败任务后恢复。手动创建不计入自动配额。

本机 M1 Pro 10 核 / 32 GB 默认并行上限为 3。执行器设置 `RUNNER_RESOURCE_PROFILE=lightweight` 时，每个轻量网页项目实际限制 2 核 / 1.5 GiB；未设置时保留原来的 2 核 / 3 GiB。调度会扣除 Docker 基础内存、其他容器实际占用及波动余量，并检查虚拟机实时可用内存和压力；旧容器按其实际限额计算，不能用较小的新预算低估。当前约 7.7 GiB 的 Docker 可在资源采样正常时支持三个轻量项目，资源紧张或采样失败时暂停新增，不中断正在运行的 Claude。暂停的项目容器也占名额，已有项目优先续跑；宿主机已占用的执行槽不会再次扣除相同内存预算。

数据库以单条 SQL 同时检查任务版本和全局运行数，防止并发超领。同一任务会话串行，不同任务并行；自动出题占用一个执行槽。容器的交互进程、超时、工作区和日志分别管理。暂停补充只停止生成新任务，队列内任务仍继续执行。

本机选用的资源预算保存在执行器工作目录的 `resource-profile.json`，格式为 `{"profile":"lightweight"}`，重启时自动恢复；显式环境变量优先。该设置只控制容器和调度资源，不改模型、网关或上下文窗口。

## 禁出题目校验

`rules/prohibited-tasks.json` 对照原文第六节（第 9–10 页）配置四类完整清单：游戏/图形、本地/桌面工具、平台/业务系统、数据可视化/前端页面，以及 Todo、常见 CRUD 模板、换皮变体的通用禁令。

规则固定注入出题和任务准备 Prompt，不能通过页面“出题范围”关闭。自动题目生成后启动独立 Codex `policy` 审核；服务端要求审核通过、完整检查四类、无命中规则和历史重复，并检查规则版本及候选题摘要匹配，才允许入队。拒绝记录保存在本机并通过工作台显示理由。手动任务与自动任务都在准备后、Claude 执行前再次审核；被拦截轮次显示为失败并保留审核原因。修改规则或重试时重新审核，不复用旧的合格结论。

语义审核使用最近 200 个跨仓库历史任务，每个任务的 Prompt 摘要最多 4000 字；精确指纹去重继续覆盖数据库中的自动题目。语义模型可能误判，有限历史窗口也不等于全库语义查重。

## 难度要求

`rules/difficulty.json` 对照文档第 5、12 页保存四级定义及四项“过于简单”特征：单文件局部/纯函数实现、无需仓库上下文、一轮即可交付且无需报错分析或规划、单文件单语言且无联调/跨服务。Codex 必须给出独立等级、命中特征 ID 和四项判断证据；程序按命中数计算，命中至少两项即拒绝，即使模型自报“困难/地狱”或 allowed=true 也不能绕过。

首轮禁止“简单”。后续针对前轮产物的小 Bug 修复例外需要已完成的前序轮次、存在的工作区和轨迹文件、产物输出，以及 Codex 对本轮确为该产物修复的判断；新任务和新增功能不能使用该例外。历史继续保留原始目标；新规则不再自动普通续写，只允许具体 Bug 追问。难度等级采用独立审核结果，页面显示四项证据、命中数量及例外理由。困难和地狱题没有额外量化上限；禁止用机械拆文件、无关技术栈或强迫多轮来凑难度。

新版规则会使旧审核失效，重试和待入队题目需按新版规则重新核验。语义判据是否命中仍依赖 Codex，程序确保计数、首轮门槛和例外资格不会被标签绕过。

## GitHub CLI 自动快照

执行器通过已登录的 `gh` 读取 GitHub 仓库信息与实际提交：自动识别 origin、查询仓库元数据、以本地完整 HEAD 查询远端提交，并验证返回的 SHA 和链接一致。快照证据包含仓库、完整 SHA、可见性、当前账号权限、默认分支与核验时间，保存到本机 `.github-snapshot.json`、任务详情和交付包。

参考仓库不干净或提交不可访问时，记录参考快照不可用；容器初始快照仍以固定镜像摘要和空目录为准。系统不自动创建仓库、提交或推送用户代码。后续轮次重新核验原始提交，不将模型产物替换为初始快照。私有仓库只证明当前 gh 账号可访问，评审者权限仍需另行核验。工作台显示 gh 连接状态，执行器每 5 分钟刷新。

## Codex 阶段与证据归档

1. **任务准备**：读取仓库和用户目标，输出执行 Prompt、任务分类、难度、技术栈、验收条件。原始目标与执行 Prompt 分开保存。
2. **环境快照**：执行器实时检查镜像摘要、容器身份、运行状态和唯一工作区挂载，保存脱敏的 `.environment.json`；Codex 读取此证据并核对初始代码清单、依赖声明及可复现范围，不在只读环境中重复访问 Docker socket。首题的业务占位和跳过测试不代表环境不可用，业务验收在 Claude 执行后进行。宿主机 GitHub 参考快照单独记录。
3. **自动评分**：只读检查本轮原始轨迹与产物，按交付完整性、指令遵循、任务规划、推理能力、执行能力输出分数和具体证据。不修复被测代码，不虚构测试。
4. **校验与交付**：Codex 检查证据与评分一致性；执行器额外校验真实 ID、轨迹及完整 SHA。通过后生成 `.runner/<task-id>/<turn-id>.ai-delivery.json`，页面可导出 Excel 或 CSV。

5. **后续决策**：Codex 基于本轮轨迹和产物决定新题、修复、结束或需要输入。每轮独立评分归档后才创建下一轮；可在调度设置关闭；独立题使用新会话，Bug 最多两轮，重复目标会暂停。

`rules/workflow.json` 保存五维分档和反馈要求。评分必须记录 When/What/Impact/正确做法、过程与产物观察，并引用可核验文件行号。逐轮 `.evidence.tar.gz` 收录轨迹、评估、阶段记录、可用的 Git diff 和受大小限制的完整工作区普通文件；清单含 SHA-256 和排除项。页面可导出当日合格轮次。完整差距见 [流程核对](docs/workflow-audit.md)。

CSV 和 JSON 始终明确标记 `AI / Codex CLI`、AI 评测用途，`attested` 不会伪造为人工确认。本模式不符合原腾讯文档项目的人工标注要求，不能冒充人工标注提交。外部平台提交不是自动步骤；界面仅可登记已实际完成的外部提交回执。

## 出题与点评表达

`rules/question-writing.json` 约束首题、准备后的实际执行题、同项目全新功能、Feature、Bug、理解和重构题：只有 0-1 代码生成首行写项目名称，其余类型不加项目名称或标题，所有题型都不加编号，正文 180–260 字、1–2 个自然段，明确受众、问题和实际操作，用 4–6 项关联功能形成网页交互流程，加入 1–2 个业务细节。基础版本可独立运行，页面布局服务于业务，不附加无关架构、数据库或实现限制。Feature 说明已有能力与本次变化；Bug 修复不加项目名称或标题，直接用同事聊天的口吻描述发生条件、实际问题和希望怎么改，不重新介绍受众，避免落实、核验、既有语义等正式措辞，保留真实复现数值。Bug、理解和重构中的 4–6 项是受影响或需要核验的已有功能，不能为了数量扩大任务。题型比例、会话上限和项目上限保持原规则。

程序检查标题、正文长度（Unicode 字符，含标点、不含标题和空白）、段落、模板标签、语气与编排信息；Codex 的独立题目审核逐项记录受众、流程、业务细节、网页交互、独立运行、布局、实现限制、题型边界和语言的依据，并检查功能与细节数量，不合格时不会交给 Claude。项目位置保存在 `projectSeries.directory` 与快照中，不再拼到题目末尾。新规则版本会使尚未执行的旧准备结果、待入队候选失效；已发送到终端的原题与原始轨迹不会因升级改写或重发。

`rules/workflow.json` 的 `writingStyle` 保留独立的点评规则：每项是一段连贯的平淡口语，不套引号、不列模板标签、不使用推测或惊讶措辞，保留事实边界，未验证的内容说明未验证。题目有单独的段落格式，不再受点评的一段话限制。

程序只自动去掉整段外围引号，其他表达问题由 Codex 最多修订一次，修订不允许改动分数、分类、难度和结构化证据，仍不合格时记录失败原因。修订不调用 Claude，不占用项目的十次 Claude 调用额度。点评直接用于页面和 Excel，结构化事实与证据通过详情和归档保留，历史执行 Prompt 和已完成记录不追溯改写；AI 来源和人工末尾复核流程保持原样。

终端出现 `Compound command contains cd with write operation` 确认时，执行器将固定提示与当前原始轨迹中的待执行 Bash 调用核对，仅为受限语法内的本项目构建、测试和本机 HTTP 联调选择一次 Yes。复杂 Shell、越界路径、外部请求、发布及发送消息等不自动确认；记录工具调用 ID、命令摘要、确认来源和时间，发送前持久化，重连不重复按键，不选永久放行，不增加用户对话次数，也不修改原始轨迹或模型配置。容器的身份、挂载和权限预检仍会实时核验。

原题已发送后的重连、评分重试，以及同会话 Bug 追问，沿用首次通过的初始代码快照，另存实时环境复核。当前代码属于 Claude 产物，不再与空骨架比较。初始记录缺失或容器、题目、镜像、挂载、终端身份不一致时停止恢复。

## 失败与恢复

阶段结果按轮次保存在 `.stages.json`。点击“重试失败阶段”重新排队同一轮：成功阶段复用，已成功的 Claude 调用不会因评分失败而重复执行。未确认的 Claude 调用保留 pending 和额度，重试仅核对同一原始 Prompt，不重新发送。容器停止后只导出归档，不重启会话；旧版宿主机会话保留历史数据，新题必须新建容器。

回写结果保存在本机文件，网络异常时重试回写。API 对同一完成凭据支持幂等回写。单执行器锁防止重复启动；异常退出残留锁会检查原 PID 已停止后回收。启动时读取任务日志并检查旧子进程身份，存活进程占用槽位且阻止同会话重试；已缓存成功执行的轮次重新排队完成后续阶段。未产生最终结果就崩溃的运行仍需人工运维确认，系统不会自动重放结果不确定的模型调用。

Claude 默认超时 30 分钟，Codex 每阶段默认 15 分钟。可通过 `RUNNER_TIMEOUT_MS` 和 `CODEX_STAGE_TIMEOUT_MS` 调整。原始事件、stderr、会话轨迹和数据包保存在 `.runner`，密钥在 `.dev.vars`，均不进入 Git 或发布包。

云端与本机 D1 数据独立。云端还需单独连接可认证的执行器；当前直接运行本机 CLI 请使用本机工作台。

## AI 评分后的人工二次确认

自动执行、Codex 评分、归档和自动续跑保持连续，不等待人工操作。在“人工二次确认”中，AI 分数和评语自动带入，人工填写本人姓名、实际核验步骤与观察结果，核对或修改五个维度后确认。AI 原评分不被覆盖，导出明确标记“人工复核（已有 AI 评估）”。这不等于原文档要求的纯人工标注流程。

低分、与 AI 分差至少 2 分、多个维度描述重复时，要求补充重点问题的二次核验依据。同一位实际检查者可完成最终确认，无须额外第三人。证据不足可标记待返工。评分与评语可预填；姓名、实际核验、本人确认不会由 AI 填入。

页面提供本轮归档的轨迹与代码变更节选，以及完整本机归档路径；节选明确标注截断，不替代全量检查。引用支持页面证据编号/行号和原 AI 已核验的文件引用。后续轮次修改工作目录不会改变已归档的证据节选。

每次草稿、确认、返工、交付登记均在 `review_history` 保存完整快照、实际填写人和服务端时间，版本冲突不会覆盖记录。完成全部有效轮次的人工核验后，填写实际外部回执方可锁定人工交付；系统不向外部平台自动提交。人工确认单独导出 Excel/CSV/JSON，AI 原评测保留自己的导出。

已有本机数据库升级一次：`npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0001_familiar_chronomancer.sql`。全新环境在初始化后也需要应用该迁移。检查：`node --test tests/human-review.test.mjs`、`node tests/human-review-api.test.mjs`；接口测试须停止真实 runner，按 `.runner/human-review-test-ids` 清理测试任务及其 review_history。

## 同一项目连续出题

自动补充一律生成新的 0-1 项目题。手动创建默认勾选“同一项目连续出题”，也可取消用于既有项目的单独目标。宿主机 GitHub 仓库仅作为参考来源，每个新项目位于容器独立工作区中的 `projects/p-<UUID>`；Codex 设计任务，Claude CLI 从零实现，而后续题基于该目录的实际产物，不更换项目。

真实 Bug 优先修复；基础项目可用后优先功能迭代，再考虑代码理解≈代码重构，最后工程化/测试。类型权重为 3:3:2:2:1:1，实际选择必须有项目证据，不能为了比例编造缺陷或拆小题。每题执行前仍独立审核禁出、雷同和难度。每轮 AI 评分和证据归档完成后自动续题，不等人工二次确认；无有价值的新题或缺少关键外部输入时结束/等待。

每道 0-1、Feature、理解和重构题使用新的 Terminal、容器、工作区和真实 SessionID。只有 Bug 修复通过 repairOf 关联紧邻的有效轮次，沿用当前会话，最多两轮，初始题加修复最多三条对话。每次发送前服务端按当前会话原子预占调用次数，失败和不确定调用占额度，最多十次。0-1 与 Feature 每项目各最多十题，失败或排除不释放题额。

验证包含 7:7:10:1:1 分布、32 条对话和 22 个会话、一次骨架生成、0-1 与 Feature 各十题、每会话最多两次修复、十次调用额度、模型不覆盖、重试不重复调用、归档与权限检查、分页和导出次数。模拟流程不等于真实模型的业务验收。

## 本轮与后续出题分离、截断续写

历史继续记录保留原始验收目标。新流程对截断记录独立评分并保留，不把续写改称 Bug，也不再自动发送普通继续；真实 Bug 才能用平淡口语在原会话追问。

每轮先评分、校验、归档，再由 Codex 规划下一题。规划失败只标记后续出题待重试，本轮数据仍能导出。页面“仅重试后续出题”只执行规划，保留本轮原评分、完成时间、归档哈希及 Claude 调用次数；若已有人工作业或提交登记、存在后续轮次或会话已结束，则禁止重排。自动续跑关闭时需先重新开启。

归档保存评分引用文件的当时副本、原引用和 SHA-256，人工核验页展示对应行附近的不可变节选；完整副本在本机归档的 cited 目录。单文件最多 10MB，引用文件合计最多 32MB，超限明确报错。界面的代码 diff 标为“本轮结束时相对初始快照的累计代码变更”，不冒充只发生于当前轮的变更。历史数据不会补造证据。

未处理完的失败轮次禁止追加新轮，防止后续改代码破坏待评分状态；后续轮次存在后禁止重跑旧轮；已评分/归档的轨迹标识和已登记回执不可覆盖。后续题型建议同时考虑当天全局已完成与在途任务，真实任务分类仍优先于权重。

检查：`node --test tests/round-context.test.mjs tests/workflow.test.mjs`、`node tests/audit-api.test.mjs`、`node tests/flow.test.mjs`。集成测试需停止真实执行器，完成后按 `.runner/audit-api-id`、`.runner/truncation-flow-id` 等本次创建的测试 ID 清理。

### 权限与代码继承核验

沿用下午配置的模型、网关和 1000000 上下文。启动前核验固定镜像隔离和工作区可读写，核对实际 Claude 进程使用 `--dangerously-skip-permissions`，允许 Bash、Read、Write、Edit、Glob、Grep，隔离额外设置、Hook 和 MCP。保留 Mac 文档要求的非 root、cap-drop ALL 和 no-new-privileges。

每轮对完整原始 JSONL 核验 bypassPermissions 和工具结果，记录 permission-rule、Hook、文件系统和外部认证拒绝的位置。权限异常阻止自动评分与合格导出；同题后续出现异常时，该会话已有记录也不再可合格导出。不会删改原始轨迹，需新建任务重新采集。免审批不替代外部 Git 服务的访问权限，也不能保证所有系统调用永远成功。

代码继承只读取上一题冻结的证据目录，逐文件校验哈希并保留执行位；从容器启动后导入，支持中断后的幂等恢复。依赖、缓存、版本库内部文件和敏感配置不继承，排除项显示在清单中；存在大小限制或非普通文件等无法自动恢复的代码时停止新题，避免从不完整代码继续。

独立验收制定计划前，用相同不可变镜像启动无网络、无项目挂载的短时容器，只检测可用命令和 Python 模块。检测结果随验收报告保存，Codex 据此准备测试工具；`venv` 模块存在不代表 `ensurepip` 或 `pip` 可用，浏览器也需安装并实际启动验证。探测及依赖准备失败只记环境阻塞，不算 Claude 的业务缺陷；探测容器按唯一名称清理，原始作业容器与轨迹不参与探测。

验收计划区分业务运行、项目开发测试和独立验收工具的依赖。开发依赖安装失败时，仍执行不依赖它的真实业务流程，保留安装失败及未执行测试的证据，不改业务源码或锁文件。无头浏览器按需要仅下载 headless shell，系统依赖准备与浏览器下载分别计时，给业务检查保留执行时间。

诊断引用统一采用执行器生成的 LF 行号视图，回车和终端控制字符转义显示；原始日志字节和 SHA-256 保持不变。只重新诊断时，先核对原执行记录、源码清单及日志，生成新的诊断证据并补全尚未写出的报告，不能覆盖已有报告或重写原始测试结果。编号视图与环境探测日志一起纳入交付归档。

## Terminal 与初始骨架

Mac Terminal 打开专用启动文件，终端内的进程执行固定镜像的 docker run -it。Runner 经该终端控制通道输入文本，Codex 阶段不调用 Claude、Docker 或控制终端。客户端版本、SessionID 和 PromptID 从原始轨迹获取，实际 TTY 写入记录，缺少终端来源时不能合格导出。

首题在空容器启动后，由 Codex 输出不包含业务实现的骨架文件清单。系统核验路径、大小和配置类型后安装并冻结清单。0-1 指项目此前不存在的全新功能；Feature 指已有能力的迭代。骨架和上题初始代码随交付证据包保存，预先准备的内容不算作 Claude 的产物。

## GitHub 初始代码快照

每道独立题执行前，执行器只读取已经冻结的 scaffoldSnapshot 或 sourceSnapshot，逐文件验证 SHA-256，在当前 GitHub CLI 账号下创建本项目专用私有仓库。每道原题对应不可覆盖的提交分支，核验远端完整文件树后才登记链接和启动 Claude；同会话 Bug 修复沿用原题提交。仓库位于执行工作区之外，不初始化或改动被测工作区的 Git 状态，也不把快照操作写进 Claude 原始轨迹。任务详情与标准表格都展示真实 GitHub Commit，镜像摘要单独保留。

已执行历史题可以从原有冻结清单补发快照，记录 backfill 和实际发布时间，不倒填提交时间、不从当前代码倒推初始状态。冻结清单缺失或哈希不一致时拒绝发布；不会用题目参考仓库或当前产物补位。上传不包含原始轨迹、模型配置或凭据。私有仓库不会自动改为公开。
